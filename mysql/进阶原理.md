```sql
SELECT
```

## 半连接(semi-join)
半连接（semi-join）是数据库执行计划中的一种连接方式，用来优化如下语义：
“是否存在匹配” 的判断
只关心有没有匹配，不关心返回匹配的具体数据

典型的例子就是：
EXISTS / NOT EXISTS
IN / NOT IN
WHERE col IN (SELECT ...)
WHERE NOT EXISTS (...) （这种应该属于anti-join反半连接）

这不是 SQL 语法的一部分，而是数据库优化器自动选择的执行方式（出现在执行计划中）。

### 数据库是怎么做的？
mysql不会先执行子查询：SELECT 1 FROM sc_swift_master b WHERE b.msg_id = swift_decoder_master.msg_id（这样会是全表扫描），而是使用反半连接：
1. 通过外部的where条件及swift_decoder_master的索引，得到所有符合条件的swift_decoder_master数据；
2. 对上面找出来的每一条记录，执行：
```sql
SELECT 1 FROM sc_swift_master WHERE msg_id = 该记录的 msg_id LIMIT 1;   -- 这里sc_swift_master有msg_id的索引
```
如果存在,就排除这条记录，如果不存在，则保留。
注意：
这里使用了索引，且不回表（只查索引层即可判断是否存在这条数据，无需读取整行数据），因此非常高效。

### 为什么不是IN (...)查询？
MySQL 优化器不会把 NOT EXISTS 自动转换成 IN 查询（也不推荐这么做）。因为对于大数据量来说，如果IN (...)里面是几千条数据，会导致SQL非常慢，index也可能失效（为什么？）。

### 如果子查询字段没有索引？
在上面的例子，如果sc_swift_master没有msg_id这个索引。
mysql会怎么执行？
由于这里进行的是相关子查询，子查询的条件依赖外层表a的字段，
因此子查询不能提前独立执行。
且MySQL 在处理“相关子查询”时，默认不会自动把它转成 JOIN 或 IN。
因此这里还是会每条外层记录都触发一次子查询。也就是循环对sc_swift_master进行全表扫描，性能很差。
